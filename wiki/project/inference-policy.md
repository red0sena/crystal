# Crystal의 질문 우선 배치·입력 반복 비교

[위키 홈](../README.md) · [이전 입력 실험](other-methods.md) · [고정 상태 판정기 비교](jepa-head-refit.md)

2026-11-04. **평가·검산 완료.**

목적은 현재 Crystal의 가중치를 바꾸지 않고 jev-brain/FlexDM의 질문 머리말과 짧은 입력 반복이
텍스트·이미지 판정에 도움이 되는지 확인하는 것이다. 64차원 합성 상태 실험과 구분하고 실제 Qwen 입력에서 비교한다.

이번 고정 Crystal에서는 질문 머리말이나 반복으로 정확도 개선을 확인하지 못했다.
질문 머리말만 추가한 차이는 텍스트−0.02%p [−1.60,+1.56], 이미지−1.48%p [−3.30,+0.27]로
두 구간 모두0을 포함했다. 반복 단독은 텍스트−3.66%p [−5.90,−1.49], 이미지−1.98%p [−3.43,−0.43]였다.
머리말과 반복을 함께 쓰면 텍스트−4.18%p [−6.65,−1.74], 이미지−3.28%p [−5.33,−1.28]였다.
각 구간은 개별95% 구간이며 다중 비교 보정은 없다. 해당 자료·모델에서의 결과로 한정한다.

raw NLL도 네 후보 중 기본이 가장 낮았다. 온도 보정은 선택지 순위를 바꾸지 않았으며,
기본 이미지의 NLL을0.828→0.818로 줄였지만 텍스트는0.705→0.707로 소폭 나빠졌다.
보정이 다른 데이터에서도 늘 개선된다고 가정하지 않는다.
이미지 반복의 평균 측정 시간은기본67.0ms에서95.1ms로 늘었다. 기본 입력 정책을 유지하는 것이 이번 결과에 맞는다.
질문 머리말·반복의 실패 원인을 이번 비교만으로 특정할 수는 없으며, 큰 causal Gemma에서의 효과가
작은 양방향 Crystal에도 그대로 옮겨간다는 근거는 얻지 못했다.

## 고정한 비교

| 정책 | 질문 목록을 본문 앞에 추가 | 짧은 user 입력 전체 반복 |
|---|---|---|
| base | 없음 | 없음 |
| header | 사용 | 없음 |
| repeat | 없음 | 사용 |
| header_repeat | 사용 | 사용 |

모델은 `runs/v3/wise80-g6-g7e2`다. 이미지 학습 전의 Crystal이며 텍스트와 이미지에 같은 가중치를 사용한다.
시스템 지시문·채팅 틀·답 코드·선택지 순서·readout·attention 방향(noncausal full attention, causal DeltaNet)은 유지한다.
기존 user 입력 앞에 질문 텍스트 목록을 추가하고, 반복 조건은 같은 user 입력 두 개를
`Read the same input again before answering:`로 잇는다. 답변을 생성한 뒤 고치는 두 단계 추론이 아니다.

이는 기본 엔진의 학습 형식을 유지한 기법 이식이다. Gemma의 `Answer: (` 틀이나 별도 토큰화까지
그대로 바꾸는 FlexDM 완전 재현과 구분한다. 이번 자료는 요청당 질문 하나라 여러 질문 목록·KV 공유의 효과는 재지 않는다.

반복 여부는 모든 조건에 공통인 base 입력의 확장 후 토큰 수가3000 이하인지로 고정한다.
텍스트는 user 입력 전체를, 이미지는 해당 입력에 포함된 이미지와 이미지 placeholder 모두를 두 번 넣는다.
반복 후 이미지 개수와 `image_grid_thw` 개수가 같은지 검사한다. 8192토큰을 넘으면 중단하며 자르지 않는다.
이미지 해상도 상한은 기존 키트와 같은1,638,400pixel이다. 비전 토큰·평균 입력 길이·반복 적용 비율도 함께 기록한다.

추론은 각 질문당 단일 예측이며 추가 모델 학습·선택지 순열 평균·근사 KV 재사용은 없다.
네 정책을 문항마다 순환 순서로 실행해 고정된 실행 순서에 따른 시간 편향을 줄인다.

## 데이터·분할·확률 보정

텍스트는 기존 `fresh-v1`의16출처1335문항을 사용한다. 이미지를 포함한 입력은 기존 heldout 구축 코드와
고정된 원본 revision에서8개 벤치마크(mmstar, mmvp, countbench, embspatial, chartqapro, seed2plus, mathvista, memotion)를 복원한다.
자료 복원 비용과 지각·공간·개수·차트·텍스트·수학·밈의 범위를 기준으로 모델 실행 전에 정한 부분집합이다.
기존17개 vision 전체 지수나 공개 보드의 점수로 부르지 않는다.

이전 연구에서 이미 결과를 본 평가 자료다. 새 비공개 성능이나 완전히 관찰하지 않은 benchmark 일반화로 해석하지 않는다.
신규 교사 label·이미지 답 학습은 사용하지 않는다. 이전 학습 당시의 데이터 겹침 감사 범위를 넘어 새로 독립성을 보장했다고 주장하지 않는다.

동일 텍스트 state, 같은 이미지 파일을 공유하는 문항을 그룹으로 묶는다. MMVP의 서로 다른 이미지 쌍도 같은 그룹에 둔다.
그룹 대표ID의SHA256 앞32bit를5로 나눈 나머지가0이면calibration, 나머지는evaluation이다.
정답이나 모델 출력은 분할에 사용하지 않는다. calibration/evaluation 사이에 같은 그룹이 들어가지 않는다.

온도는 입력 모달리티×정책×질문 종류마다calibration의 출처 균형 NLL로 적합한다.
범위는T=.05~20이며, 해당 종류의 calibration 문항이20개 미만이면T=1을 유지한다.
yes/no 편향 보정은 쓰지 않는다. 신경망 가중치 학습은 없지만 정답을 이용한 소수의 보정 계수 적합은 한다.
최종 비교는evaluation 그룹만으로 하며, 원래T=1 점수와 보정 후 점수를 모두 기록한다.
양의T는 선택지 순위를 바꾸지 않으므로 정확도와 확률 보정의 효과를 구분한다.

## 지표·검산·실행

주 지표는출처 macro 정확도다. NLL·Brier·ECE15bin·출처별 결과를 함께 남긴다.
보조 all-rows 집계는이미 calibration에 사용한 정답을 포함하므로 descriptive로 표시한다.
paired bootstrap5000회는 각 출처 내부의 입력 그룹을 복원 추출하고 모든 정책에 같은 추출을 쓴다.
95% 구간은 고정된 모델·출처·calibration 계수에 조건부이며 새 학습 seed나 새로운 benchmark의 변동성을 포함하지 않는다.
여러 비교의 구간에 복수 비교 보정은 없다. 가장 잘 나온 정책만 선택해서 보고하지 않는다.

추론 시간은batch1에서CUDA를 동기화하고 렌더링·토큰화/processor·GPU 전송·forward·logit 읽기를 측정한다.
원본 이미지 파일의디스크 읽기는 공통 준비 단계로 분리해 따로 기록하며, 모델 로딩과warmup은 제외한다.
기존 보드 엔진의 end-to-end 지연과 절대값을 직접 비교하지 않는다.

- [입력·이미지 반복·분할·보정·집계 검사](../../tests/test_v3_inference_policy.py)

  소스마다 고정한 한 문항×네 정책을 실제 모델에서 재실행한다. 전체 모델 재실행으로 부르지 않는다.
