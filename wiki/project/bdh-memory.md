# BDH 연상 메모리 코어와 학습 데이터 양 비교

2026-10-19~20. 사용자의 요청은 더 급진적인 구조를 실제 적용하고, 이전 작은 차이가 학습 데이터 부족 때문인지 확인하는 것이다. 단일 모델의 상위 판정 계산을 교체하며 예측·모델 가중치를 조합하지 않는다.

## 원문과 구현 범위

[BDH-CQ](https://arxiv.org/abs/2608.09888) §3.3은 차원·정확한 상태 업데이트·내부 구현이 비공개라고 명시한다. 따라서 그 시스템의 재현이나 ARC 결과의 재현으로 부르지 않는다. 공개된 [BDH-GPU 코드](https://github.com/pathwaycom/bdh/blob/2b0d7a45b058d4309c84a10e0768d541fe18bdc2/bdh.py)와 [원 논문](https://arxiv.org/abs/2509.26507)을 바탕으로 Qwen3.5에 맞춘 별도 retrofit을 구현했다. 공개 저장소 README도 Sudoku 성과가 현재 공개 코드의 즉시 재현 결과가 아님을 명시한다.

공식 코드·README·MIT license를 commit `2b0d7a45b058d4309c84a10e0768d541fe18bdc2`에 고정하고 run에 원문·hash를 저장했다. 원 저작권·허용 조건은 [license](../resources/bdh-license.txt)에 보존한다.

## 바뀐 계산

기본 g4b는 native hybrid24층과 마지막 토큰의 코드 head를 사용한다. 새 구조는 앞16층을 언어 encoder로 쓰고, **남은8층의 실행을 BDH 방식의 메모리 갱신3회로 대체**한다. 기존 뒤8층은 frozen 상태로 체크포인트에 보존하지만 새 forward에서는 실행하지 않는다.

메모리 코어는 각 토큰의 상태 x에서 다음 계산을 한다.

1. `phi = ReLU(x U)`로 양수 feature를 만들고 BDH의 paired feature RoPE를 적용해 q를 만든다.
2. 현재 요청의 연상 행렬 `M = sum_t q_t outer x_t`를 만든다. `q_i M`에서 자기 자신의 기여를 뺀다. T×T 행렬을 만들지 않는 형태와 명시적 dense 형태의 출력·gradient 일치를 검사했다.
3. 읽은 값을 normalize한 뒤 `psi = ReLU(read V)`를 계산한다.
4. `phi * psi`의 coactivation을 W로 투영하고 residual·LayerNorm으로 상태를 갱신한다. 같은 U/V/W로3회 반복한다.
5. 원래 마지막 RMS norm과 코드 head로 점수화한다. 뒤8개 native층을 통한 직접 우회 경로나 새0게이트는 없다.

U/V/W는 제거한 첫 native층(0-based16)의 up/gate/down projection을 복사해 초기화한다. 새 코어의 학습 파라미터는11,010,048개다. head4개, head당 feature896, state1024차원이다. 공개 예제의 매우 넓은 feature 차원을 그대로 사용한 것은 아니며, pretrained projection의 폭3584를 재사용한 설정이다.

원래 공개 BDH의 strictly causal retrieval 대신 현재 Decision의 전체 문맥 읽기에 맞춰 양방향·self 제외 retrieval을 쓴다. 토큰 수에 따라 읽기 크기를 조절하고 per-head LayerNorm을 적용한다. RoPE 전의 firing과 coactivation은 양수지만, RoPE가 적용된 kernel의 모든 연결 weight가 양수라는 뜻은 아니다. 이 retrofit에 대한 해석 가능성·monosemanticity·범용 추론 능력을 검증한 것은 아니다.

[구현](../../qwen_decision/v3/bdh_memory.py)은 요청별 중간 상태를 tensor로 전달하고 매 refinement에서 메모리를 다시 만든다. 요청 사이에 남는 상태나 추론 시 weight 업데이트가 없다. 모델은 전용 `bdh_memory.load`와 `logits`로 복원해야 하며 plain Transformers/기본 엔진 로딩과 같은 계산이 아니다.

## 왜 데이터 양을 따로 비교하는가

전체 gold6 학습 파일은699,960행이지만 직전 구조 실험은12,290행 풀 중8,192 draw/512 update만 사용했다. 그512 update에서는 셔플된 풀의 첫 pass이므로8,192개 서로 다른 행을 사용한다. 원래 판정 체크포인트가 훨씬 많은 학습을 거친 점과 새 구조의 적응 예산을 구분해야 한다. 이를 전체 원본 데이터가 작다는 근거로 쓰지는 않는다.

이전 workspace에서는 선택지 성분을 제거해도512개 선택이 바뀌지 않았다. 가설 출구 버전은33개가 바뀌었지만 같은256스텝의 native보다0.81%p 낮았다. 따라서 데이터 부족, 새 경로 사용 부족, 이미 학습된 기존 계산을 교체하는 데 따른 적응 비용을 구분해야 한다.

관련 선행연구도 구조 교체 후의 **동작 정렬**을 별도 학습 문제로 다룬다. [LoLCATs](https://arxiv.org/abs/2410.10254)는 선형 attention이 기존 softmax attention의 출력을 맞추는 MSE 학습을 먼저 하고, 이후 LoRA로 남은 오차를 적응시킨다. [Mamba in the Llama](https://arxiv.org/abs/2408.15237)도 pretrained projection 재사용과 단계별 정렬·distillation을 구분한다. 이번 정답CE 실험에는 그 정렬 단계를 넣지 않았다. 따라서 단순히 고유 문항 수만으로 새 구조의 최적 학습 조건을 판단할 수 없으며, 이 연구들의 결과를 우리 BDH retrofit의 개선 근거로 쓰지는 않는다.

## 사전 고정한 세 군

| 군 | 구조 | 학습 고유 문항 | 노출 수 | update |
| --- | --- | ---: | ---: | ---: |
| bdh_large | native16 + BDH3회 | 16,384 | 16,384 | 1,024 |
| native_large | 기존 native24 | 16,384 | 16,384 | 1,024 |
| bdh_small | native16 + BDH3회 | 4,096 | 16,384 | 1,024 |

작은 군은4,096행을4회 반복한다. 큰 군은 작은 군을 포함한16,384행을 각각1회 사용한다. 두 데이터는100출처이며 각 출처의 행 수가 정확히1:4다. 모든 update의16개 출처 순서까지 맞춘다. 서로 다른 state는 작은 군4,023개, 큰 군15,916개다. 행 수4배가 모든 의미적 정보량의4배라는 뜻은 아니다.

모든 군은 같은g4b·batch16·seed41·body LR3e-6·warmup64/cosine·FP32 master AdamW·정답CE·같은 증강 규칙이다. 새 memory projection LR1e-4다. 실제로 쓰이는 언어 파라미터·tied embedding/head를 학습하고 vision과 미실행 뒤8층은 frozen으로 둔다. 모델/seed 평균·새 teacher label·추론문은 없다.

이것은 세 군 비교다. **큰 데이터에서 구조 차이**, **BDH 안에서 고유 데이터 양 차이**를 비교한다. native_small이 없으므로 architecture×data의 완전한2×2 상호작용 검정은 아니다. 파라미터 수·FLOPs·두 데이터의 토큰 총량도 일치하지 않는다. native_large와 bdh_large는 매 update의 실제 prompt hash까지 같아야 비교가 진행된다.

같은1,024 update 결과가 주 비교이며256/512 snapshot의 최선은 보조로 구분한다. 원래부터 공개된 selection4,147문항/77출처를 사용한다. 구조가 native_large보다 최소0.5%p 높을 때만 새로운 감사된 확인셋의 준비를 검토한다. 이 run은 새 확인셋을 자동으로 열지 않는다.

작은 군에서 고정512문항의 probe를 뽑았다. 최종1,024스텝에서는 세 군 모두 이 문항을 학습했다. 중간256/512 시점에는 큰 군에서 아직 보지 못한 probe가 있으므로 중간 probe를 같은 노출 수의 train 정확도로 해석하지 않는다. 최종 train/selection 차이와 학습곡선은 과적합·적응 미완료 진단의 참고로 사용한다.

큰 데이터는 기존 전체 gold2/3/6 학습1,299,919행 제외 감사를 통과한 같은 selection을 유지하면서, hash가 고정된 gold6 training에서만 추출했다. 새 train/selection의 직접 ID·문서·정규화 state 분리도 검사했다. 모든 semantic paraphrase나 foundation pretraining 비노출을 보증하는 감사는 아니다.

## 실행과 검증

계획·입력·source snapshot·학습 로그·가중치·선택 예측은 `runs/bdh-memory/data4x-v1/`에 저장한다. `PYTHONPATH=external/decision-index .venv/bin/python -m qwen_decision.v3.bdh_experiment prepare`, `smoke`, `run` 순서로 실행했다. 같은 명령의 기존 출력 덮어쓰기는 거부한다. 실제 입력 hash와 public source commit을 manifest에 고정했다.

linear associative 계산의 dense 출력/gradient 비교, 상위층 미실행·패딩·checkpoint replay·요청 독립성·저장 복원 테스트를 포함해 관련67개 테스트가 통과했다. 실제0.8B의3스텝 smoke는 모든 trainable gradient가 유한하고 세 memory parameter에 nonzero gradient가 도달했으며, 저장/재로딩 예측·확률 차이는0이었다. 학습에 사용되는 파라미터는597,365,632개이며 미실행 native8층의 저장 공간은 여전히 체크포인트에 남는다.

학습 전 새 구조의 selection 출처 평균은54.7217%였다. 원래g4b의71.4304%에서 크게 낮아져 이번 변경은 기존 판정 함수를 보존하지 않는다. 초기 점수를 회복하는 것과 학습한 native 대조군을 넘어서는 구조 이득을 구분한다.

## 데이터가 작아서였는가

**새 구조의 추가 학습에 쓰는 고유 문항 수는 이번 성능에 영향을 줬다.** 전체 gold6 파일699,960행의 존재와 실제 retrofit에서 사용한4,096/16,384행을 구분해야 한다. 같은 문항을 네 번 보는 것보다 고유 문항을 늘리는 편이1.69%p 높았다. 다만 native_small을 학습하지 않았으므로 원본과 BDH의 데이터 민감도가 서로 다른지는 검정하지 않았다. 같은 초기 모델·한 seed·한 번의 nested sampling 결과이며 다른 표본·seed에서의 변동은 이 비교에 포함하지 않는다.

그렇다고 이전의 모든 미미한 구조 차이를 데이터 부족으로 설명할 수는 없다. 이전 workspace의 약한 경로 영향과, 이번 교체의 큰 초기 손실은 다른 현상이다. 이번 BDH는 약20.23%p를 회복했지만 같은 추가 학습을 받은 native에는0.60%p 못 미쳤다. 이미 학습된 상위8층의 계산을 없앤 데 따른 적응 비용도 함께 고려해야 한다. 더 긴 학습·더 넓은 memory·별도 정렬을 하면 native를 넘을지는 이 실험에서 확인하지 않았다.

## 최종 감사

`PYTHONPATH=external/decision-index .venv/bin/python -m qwen_decision.v3.bdh_audit`를 별도 프로세스로 실행했다. [최종 JSON](bdh-memory-results.json)에 입력·학습·가중치 hash와 결과를 기록했다. 학습 구현은 prepare 당시 snapshot, 감사 구현과 통계/정규화 helper는 `audit-source-v1/` snapshot으로 보존한다.

- 세 저장 모델 각각 selection4,147문항 전체의 재로딩 **예측 불일치0·최대 확률 차이0**. 큰 데이터의 native/BDH1024개 prompt hash와 세 군의1024개 출처 순서 hash가 모두 일치했다.
- 출처를 유지하고 문서 그룹을 재표집한 paired bootstrap5,000회95% 구간: **BDH−native −0.5964%p [−1.6430,+0.3801]%p**(145회복/158악화), **큰−작은 BDH +1.6884%p [+0.2735,+3.1205]%p**(328회복/230악화). 반복 사용한 selection의 탐색적 구간이며 독립 확인·seed 변동·학습 표본 변동에 대한 구간은 아니다. 첫 구간은0을 포함하므로 native가 확실히 우월하다는 검정 결론도 내리지 않는다.
- 실제 native 블록 호출은 앞16개 각각1회·뒤8개0회였다. 코어3회 수동 replay와 실제 hidden의 최대 차이는0. 각 갱신의 상태 변화 norm은 이전 상태 norm 대비68.53/42.76/21.60%였다. 코어 U/V/W의 초기 대비 weight 변화 norm은 각각16.22/4.78/8.20%였다.
- 고정512문항에서 memory 읽기를0으로 만들면 **48개 선택**이 바뀌고 최대 확률 차이.89828이었다. 출처 평균은74.6831%→73.6379%였다. 새 경로가 단순히 비활성인 경우는 아니지만, 이 제거 실험은 별도로 학습한 native16층 대조군이나 메모리 구조의 정확도 개선 증명이 아니다.
- 같은512문항에서 추론 반복 수1/2/3/4/6회의 출처 평균은74.3955/74.7124/74.6831/71.6837/58.7709%였다. 학습은3회로만 했으며 더 많은 반복이 자동으로 좋아지지 않았다. 이미 노출된 표본의 사후 진단이며2회 등을 재선택하거나 확인셋을 여는 데 쓰지 않았다.
- GPU 패딩/단독 입력4문항에서 선택 불일치는0, 최대 확률 차이는.005314였다. BF16 확률의 bitwise 패딩 불변을 주장하지 않는다. float32의 수학적 패딩·dense 연산/gradient 동치 검사는 단위 테스트로 별도 통과했다.
- 준비된 동일 GPU 입력512문항을 경로별 warmup 후3회 번갈아 실행한 중앙값은 **native8.5586초, BDH6.6067초(−22.8065%)**였다. 서로 학습한 두 모델의 계산 경로 비교이며 tokenization·loading·서비스 전체 호출은 포함하지 않는다. 정확도 우위가 없어 현재 판정 모델의 대체 후보로 채택하지 않았다.

## 길이·후보 수의 사후 진단

아래는 최종 모델을 이미 노출된 selection에서 나눈 기술적 진단이다. 별도 확인이나 새 후보 선택 기준이 아니다. bin마다 포함되는 출처가 다르므로 전체 macro의 가중 분해로 사용하지 않는다.

| 입력 길이 | 문항 | native_large | bdh_large | BDH−native |
| --- | ---: | ---: | ---: | ---: |
| ≤512토큰 | 3,097 | 76.5660% | 76.5413% | −0.0247%p |
| 513~1,536토큰 | 904 | 80.1285% | 77.4296% | −2.6989%p |
| >1,536토큰 | 146 | 69.3396% | 60.8314% | −8.5082%p |

두 군 모두 추가 학습의 원본 입력 길이를1,536토큰 이하로 제한했다. BDH에서 긴 문맥으로의 확장과 많은 후보를 구분하는 계산이 약해졌을 가능성이 있다. 후보≤4개 구간의 차이는−0.1240%p,5~16개는−1.9999%p,16개 초과는−4.5885%p였다. 길이와 후보 수는 서로 얽히므로 어느 하나를 원인으로 분리하지 않는다. 이 결과는 데이터 **개수** 외에 길이·후보 수의 학습 분포와 새 메모리의 표현 용량도 확인할 이유를 제공하며, 연상 행렬의 간섭이 원인임을 직접 검증한 것은 아니다.
