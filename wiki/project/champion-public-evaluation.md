# 텍스트·비전 공식 공개 평가 실행

2026-11-04. [1B 이하 두 트랙 1위 프로젝트](champion-v1.md)의 공동 파일럿을 선두와 공식 공개 채점 방식으로 비교한다. 내부 진단 정답률을 공개 지수나 비공개 Full로 바꾸어 부르지 않는다. 새 학습은 이 비교가 끝나고 부족한 과제군을 확인한 뒤 설계한다.

## 평가 범위와 입력 검증

| 모달리티 | 범위 | 우리 후보 | 현재 1B 이하 선두 |
|---|---|---|---|
| 텍스트 | 점수에 포함되는 37개 패널, 110,087요청 | 원본 Qwen에서 시작한 g7 공동 파일럿 | GLiClass v4 edge |
| 비전 | 공식 11개 벤치마크, 12,210요청 | 같은 공동 파일럿, decide 형식 | QEV-0.8B accurate |

텍스트 suite는 고정된 자체 Hub 백업에서 복구했다. gzip 전체와 selected-rows 내부 해시는 공식 원본과 다르며 이를 숨기거나 strict 검증 성공으로 바꾸지 않는다. 차이는 점수에 포함되지 않는 RouterBench(6)·SGD(10)의 재구성 차이다. **37개 점수 반영 패널 전부에 대해 실제 state·questions를 공식 키트의 `model=jev-1.13.0`를 포함한 payload 해시 규칙으로 다시 계산했고, 공개 참조 결과의 실제 입력과 일치했다.** 이 검증은 저장된 해시 필드끼리만 비교한 것이 아니다.

점수에 포함되지 않는 여섯 catalog(6, 10, 24, 26, 27, 34)는 새 로컬 실행에서 생략한다. 따라서 키트의 전체 suite `complete=false`는 그대로 보존하고, 별도의 `counted-completeness.json`으로 점수 반영 패널의 처리·응답 완결성을 기록한다. 미지원·오류는 원래 채점기의 분모에 남는다. 연결된 질문과 후보 그룹은 쪼개지 않는다.

비전은 원본 데이터의 고정 revision에서 복구했다. Winoground 접근 권한 연결 후 해당 소스를 포함한 12개 소스의 문항·이미지 해시, 11개 벤치마크의 run ID·payload 해시를 전부 공식 pin과 대조했다. `vision-verification.json`의 `ok=true`를 확인했다. Mind2Web의 표식 렌더링은 Microsoft corefonts의 Arial Bold를 데이터로 추출해 사용했으며, 해당 이미지 해시도 공식값과 일치했다. 폰트 설치 실행 파일은 실행하지 않았다.

공동 파일럿에서 실제 선택한15,149개 고유 학습 이미지의 SHA256을 이번 비전 전체 평가 이미지와 대조해 정확 일치0건을 확인했다(`pilot-public-exact-image-audit.json`). 이는 리사이즈·크롭 등을 포함한 근사 중복 검증을 대신하지 않는다. 파일럿의 전체 보드 근사 중복 감사는 아직 완료되지 않았으므로 제출 가능한 오염 없는 최종 모델이라고 주장하지 않는다. 후속 학습 확대 전에 이 감사를 마쳐야 한다.

## 선두의 공개 원본 결과 검산

[knowledgator/decision-index-results](https://huggingface.co/datasets/knowledgator/decision-index-results/tree/01eda5c0272ba446f1d16a3876efc853a4911844/runs/gliclass-v4-edge)의 원본 140,620요청을 고정 revision·파일 SHA로 복구했다. 이 중 제외 규칙 적용 후 점수에 반영되는 110,087요청은 ok 110,085·unsupported 2다. 같은 키트로 공개 지수 **47.49**를 재현했다.

이는 저자가 공개한 예측의 재채점이다. 현재 GPU에서 직접 실행한 결과와 별도 디렉터리에 보관한다. 원본 실행 환경은 Torch 2.12.1·Transformers 5.20.0·GLiClass 0.1.20·RTX PRO 6000이며, 현재 로컬 실행은 기존 다운로드 비교와 같은 Torch 2.10·Transformers 5.18 환경이다. 환경 차이 또는 수치 차이가 있을 수 있으므로 로컬 결과가 원본 점수와 일치한다고 미리 가정하지 않는다.

## 고정된 추론과 실행 순서

선두 모델·공식 추론 코드·가중치 provenance는 [직접 비교 기록](champion-leader-comparison.md)을 재사용한다. 새 선두를 학습 교사나 초기값으로 쓰지 않는다. 문항별로 프롬프트·온도·픽셀 예산을 조절하지 않는다.

우리 텍스트의 varlen 패킹 최적화는 검증에서 기존 SDPA 판정과 24문항 중 23개만 일치했고 최대 확률 차이는 0.03118이었다. 이 최적화는 본 평가에 채택하지 않았다. **기존 `V3Engine`·`Scorer`의 SDPA 경로, 원래 프롬프트와 tied readout, orders=1을 사용한다.** 불일치 기록과 처음 실패한 서비스 로그를 삭제하지 않는다. 이는 학습 실패를 의미하는 결과가 아니라 실행 경로 검증이다.

우리 텍스트와 비전 두 엔진을 별도 프로세스로 사전 점검한 뒤 입력·가중치·추론 코드·키트 코드/상수·이미지 파일을 해시로 고정한다. 우리 텍스트는 37개 과제와151개 선택지·64개 질문·최장문 입력을 기존 SDPA 경로로 통과했다. GLiClass 로컬 전체 실행은 native DeBERTa의 장문 attention에서 현재 가용 GPU 약16GB를 초과해 사전 점검 단계에서 중단했다. 다른 프로세스의 GPU 점유를 해제하거나 입력을 줄이지 않았다. 텍스트 선두 기준은 앞서 전체 입력 대조와47.49 재현을 통과한 저자의 공개 예측을 재사용한다. 이는 새 로컬 전체 실행이 아니며, 이미 완료한1,335문항 직접 비교와도 구분한다.

현재 GPU에서 우리 텍스트 → 우리 비전 → QEV 비전을 순서대로 실행한다. 긴 실행은 systemd 사용자 서비스로 유지하며 요청별 결과·진행 상태·실패 traceback을 남긴다. 재개 시 완료 요청은 건너뛴다. 첫 단계에서 중단된 preflight 로그와 계산 전의 계획은 별도로 보존한다.

실제 실행 서비스는 `champion-public-eval-v1c`이며 로그는 `pipeline-reference.log`다. 세 엔진 모두 사전 점검과 불변 계획 고정을 완료했고, 21:27 KST에 우리 텍스트 전체 실행이 시작됐다. 처음450요청이 오류·미지원 없이 처리된 것을 확인한 뒤 지속 감시를 중단한다. 이후 진행 상태는 각 실행의 `status.json`으로 확인한다.

## 산출물과 해석

- 실행·검증 원본: `runs/champion-v1/public-eval-v1/`.
- 텍스트 검증: `text-counted-verification.json`, 원본 선두 검산 `gliclass-published-score/parity.json`.
- 비전 검증: `vision-verification.json`, 소스별 복구 보고서.
- 모델별 불변 계획: `<job>/plan.json`; 요청별 결과와 원래 키트 `scores.json` 또는 `vision-scores.json`을 함께 보관한다.
- 완료 시 `comparison.json`과 [공개 비교표](champion-public-comparison.md)를 자동 생성한다. 일부만 끝났으면 완료된 실행만 표시한다.

공개 지수의 차이는 내부 정답률 차이와 별도로 해석한다. 텍스트는 F1·nDCG·요청별 정확 일치 등 각 패널 원래 metric과 chance 보정을 그대로 사용한다. 비전은 공식 11개 가중치와 chance 보정을 사용한다. 텍스트 Full은 비공개 same 60% + new 40%, 비전 Full은 공개 50% + 비공개 50%이므로 공개 결과만으로 1위를 선언하지 않는다. 최종 목표는 계속 두 트랙 모두의 공식 Full 선두다.
