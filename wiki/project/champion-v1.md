# 1B 이하 텍스트·비전 1위 프로젝트

2026-11-04 시작. 사용자 목표는 Jev Decision Index의 **텍스트·비전 두 트랙 모두 1B 이하 1위**, 가능하면 큰 격차를 내는 것이다. 원본 Qwen에서 시작한 [공동 학습 파일럿](champion-joint-pilot.md)은2,048 update·네 평가·회전 진단·저장/복원 검증까지 완료됐다. 파일럿의 내부 지표를 공식 순위 달성으로 부르지 않는다. 기존 Crystal은 참고 기준이며 프로젝트의 성공 기준은 두 트랙의 1B 이하 전체 선두를 넘는 것이다.

**최신 텍스트 데이터 기준은 `v3-gold7`의999,961행·113출처다.** 처음에 `v3-gold6` 70만 행을 복구·감사한 것은 이전 버전의 참고 기록으로 보존한다. 그 결과를 g7 감사로 사용하지 않는다. Hub의 g7 원본 manifest·학습 설정·best·최종 merge를 확인한 [g7 검토 증거](champion-v1-g7-review.json)를 이번 계획의 데이터·모델 계보 기준으로 삼는다.

## 이번 프로젝트에서 고정한 사용자 지시

- 원본 공식 사전학습 모델에서 새로 시작한다. 기존 Crystal, 이미지 파인튜닝, QEV 등의 학습된 가중치를 초기값으로 쓰지 않는다.
- 기존 위키·저장소·Hugging Face에서 얻은 지식과 구현을 적극 재사용한다. 이미 답이 나온 비교를 다시 시작하지 않는다.
- 우선 현재 호스트의 GPU를 사용한다. 다른 머신은 이번 실행에 사용하지 않는다.
- 기존 교사·증류 금지 방침을 유지한다. 기존 도구 출처3개(`apibank-train`, `tools-percall`, `when2call-train`)와 g7의 `minicheck-synth`만 과거 사용자 허용 기록에 따른 예외다. MiniCheck의 고정 원본 manifest는 2026-10-19 허용을 명시한다. 이 예외를 다른 출처·새 교사 호출로 확대하지 않는다.
- 긴 작업을 계속 감시하지 않는다. 진행 상태·완료·실패를 파일로 남기고, 결과와 검산을 보존한다.
- 기존 Crystal을 넘는 것을 최종 목표나 다음 실험 선택의 단독 기준으로 삼지 않는다. 두 트랙의 전체 선두와 공식 점수 구조를 기준으로 우선순위를 정한다.

## 목표와 현재 기준

[보드 원본](https://huggingface.co/spaces/multimodalart/jev-decision-index)의 Space revision `01156854e703d6e58be85beb676a8b99d12e0be6`을 11-04에 고정했다. 텍스트 데이터 생성일은 10-29 14:04 UTC, 비전은 10-29 17:22 UTC다. 확인 날짜와 실제 데이터 생성일을 구별한다.

| 트랙 | 1B 이하 최고 Full | 우리 공식 기록 | 프로젝트의 초기 도전 목표 |
|---|---:|---:|---:|
| 텍스트 | GLiClass v4 edge **31.21** | text-only Crystal **29.37**, 점수순 세 번째 | **36.3 이상**, 제출 시점 최고점보다 5점 이상 |
| 비전 | QEV-0.8B **44.81** | 미제출 | **50.0 이상**, 제출 시점 최고점보다 5점 이상 |

이는 달성한 결과나 예상 성능이 아닌 목표다. 실제 순위는 공식 비공개 평가를 받아야 확인할 수 있다. 표의 세 번째는 점수순 위치이며 보드의 통계적 동순위와 구별한다.

파라미터는 모델 이름 대신 실제 served parameters를 기준으로 한다. ViT·임베딩·head·동시에 보유하는 어댑터까지 세어 총 1,000,000,000 이하여야 한다. 불명인 참가자는 작은 모델 순위 집계에서 제외한다. 여러 큰 모델을 번갈아 호출하는 방식으로 이 한도를 우회하지 않는다.

현재 원본 파일의 tensor header에서는 언어·readout752,393,024개, vision100,592,896개, MTP20,452,864개를 확인했다. 저장된 총 원소는873,438,784개다. 통상 serving에서 쓰지 않는 MTP를 제외하면852,985,920개로 보드의 Qwen 크기와 맞는다. 최종 제출에서는 실제 로딩·사용하는 모듈과 추가 어댑터를 다시 세고, 이 원소 합을 runtime 검산 대신 쓰지 않는다.

**점수 구조가 다르다.** 텍스트 Full은 공개 척도로 등화한 비공개 same 60% + new 40%이고 공개 점수는 포함하지 않는다. 비전 Full은 공개 50% + 비공개 50%다. 따라서 텍스트 공개 점수나 우리 로컬 비전 10개 지수를 공식 Full로 대체하지 않는다.

### 최신 g7 데이터와 최종 모델 계보

Hub 고정 revision의 실제 manifest와 merge를 재확인했다.

| 항목 | g6 | 최신 g7 |
|---|---:|---:|
| train 문항 | 699,960 | **999,961** |
| train 출처 | 104 | **113** |
| dev 문항 | 30,832 | **33,821** |

추가9출처는 `aegis-prompts`, `argsme-train`, `csqa2-train`, `ezstance-train`, `minicheck-synth`, `nvd-cve`, `poem-pairs-gen`, `pstance-train`, `scruples-train`이다. 기존 출처 quota도 달라져서 g7을 단순히 g6에30만 행을 덧붙인 파일로 가정하지 않는다.

g7은 원본 Qwen에서 noncausal full FT·CE, LR3e-6·effective batch32·padding0으로3epoch 학습했다. 총93,747 update 중 best는62,498 update, 정확히2epoch이며 dev 출처 평균 정답률은0.816137이다. 당시 큰 데이터 full FT와 이후16k LoRA 연구는 서로 다른 실험이므로, LoRA가 최종 g7을 이미 이겼다고 주장하지 않는다.

보드 text-only Crystal의 `wise80-g6-g7e2`는 원본을 기준으로 g6 last와 g7 epoch2의 변화량을 각각0.5씩 섞고0.8배 적용한 것이다. 즉 **0.2×원본 +0.4×g6 +0.4×g7 epoch2**다. 최신 데이터는 g7이며, 제출 가중치는 이 조합이라는 점을 함께 기록한다. 새 학습 초기값은 사용자 지시대로 원본이다.

g7 train/dev를 고정 revision에서 복구했고 Hub LFS SHA256과 당시 학습 manifest의 SHA256이 일치한다. g7 추가9출처의 원본 manifest도 복구해 라벨 출처를 대조했다. `minicheck-synth`는 로컬 g6 registry에는 없지만 고정한 원본 manifest에 사용자 허용 날짜가 명시돼 있다. 공동 파일럿 auditor는 이 예외와 추가 출처를 명시적으로 처리한다. 최신 데이터에 로컬 g6용 auditor를 그대로 적용하지 않는다.

## 먼저 고칠 평가

현재 보드의 텍스트 공식 panel 37개를 재집계하면 **단순 정답률형21, 요청 전체 exact-match3, F1계열11, nDCG2**다. 이전 위키의 “정답률17개”를 그대로 사용하지 않는다. 전체 목록과 계산 입력은 근거 JSON에 있다.

`proxy_eval.py`·`fresh_eval.py`의 출처 평균 정답률은 계속 일반화 진단으로 쓰되, 공식 지표를 재현했다고 부르지 않는다. 최종 후보는 다음을 함께 기록한다.

1. 공개 suite는 kit의 기존 scorer로 F1, nDCG, 요청별 exact-match와 실패 분모까지 그대로 계산한다.
2. 내부 dev는 정답 NLL, 출처별 정확도, 클래스별 recall·F1, 양성 예측 비율을 기록한다. 양성/음성 또는 선택지 의미가 같은 항목끼리만 클래스 지표를 합친다.
3. 여러 질문이 연결된 요청은 그룹을 보존한다. 검색 순위는 query별 후보 그룹을 보존한다. 한 문항씩 쪼갠 정확도로 대체하지 않는다.
4. 비전은 Winoground를 포함한 **공식11개**와 해당 가중치를 지원한다. 과거 Winoground를 뺀 10개 지수49.89와 공식11개 QEV52.73의 차이는 직접 비교하지 않는다.
5. 기존 fresh·JEVal·vision-heldout는 이미 반복 관찰된 진단셋이다. 새 프로젝트라는 이유로 blind라고 다시 이름 붙이거나 기존 restricted 분할을 초기화하지 않는다. 최종 확인용 새 데이터는 후보 선택 전에 따로 고정한다.

전역 양의 temperature는 선택지 argmax와 이진0.5 판정을 바꾸지 않는다. 확률 품질 개선과 결정 개선을 나눠 기록한다. 입력별 bias·문턱값 학습은 별도 후보로 취급하고, 평가 라벨로 맞추지 않는다.

## 새 학습의 우선순위

**파일럿 완료 후 우선순위 정정:** 사용자가 두 트랙의 전체1위를 다시 강조했다. 다음 단계는 현재 후보의 공식 방식 공개 평가와 선두의 공개된 과제별 결과를 같은 척도로 대조하는 것이다. 텍스트37 panel의 F1·nDCG·요청별 exact-match와 비전11개 채점 경로를 우선 완성하고, 공개·비공개 Full·내부 정답률을 분리한다. 공개 평가만으로 비공개 Full이나 순위를 예측해 단정하지 않는다.

**선두 직접 실행:** 사용자 요청으로 [GLiClass v4 Edge와 QEV-0.8B를 다운로드해 비교](champion-leader-comparison.md)한다. 가중치·공식 추론 코드·모델별 native 입력 형식·픽셀 예산을 확인한 뒤, 먼저 현재 파일럿과 같은 텍스트1,335·이미지2,184 진단 문항에서 문항별 격차를 측정한다. 이 내부 직접 비교와 공식 suite/Full을 구별한다. 새 교사 데이터나 기존 선두 가중치를 학습 초기값으로 사용하지 않는다.

**직접 비교 완료:** 위 진단에서 GLiClass70.14% 대 공동 파일럿63.01%, QEV61.31% 대 공동 파일럿59.62%였다. 미지원0건이며 가중치·입력·코드 해시 검산과 native 추론 검증을 통과했다. 선두 대비 내부 격차는 각각−7.13%p·−1.69%p다. 큰 격차는 epistemic reasoning·SWAG·CountBench 등에서 관측됐고, 파일럿이 앞선 과제도 있다. 원인과 학습 확대 방향을 이 관측으로 조사하되 공식1위·비공개 Full과 동일시하지 않는다.

**공식 공개 평가로 확대:** [공개 평가 실행 기록](champion-public-evaluation.md)에 텍스트 37개 패널·110,087요청과 비전 공식11개·12,210요청의 입력 검증과 실행 방식을 정리했다. 점수 반영 텍스트 전부의 실제 payload를 공개 참조 결과와 대조했고, 비전은 Winoground와 Mind2Web 렌더링을 포함해 공식 문항·이미지·payload 해시 검증을 통과했다. GLiClass 저자의 공개 원본 예측은 같은 키트로47.49를 재현했다. 우리 텍스트·비전 및 QEV 비전의 로컬 실행과 GLiClass 저자의 원본 재채점은 구별한다. GLiClass의 장문은 현재 가용 GPU 메모리를 넘어 공개 원본을 재사용한다.

**11-05 학습 확대:** 사용자 지시에 따라 [약점 분석과 공동 학습 확대](champion-joint-scale.md)를 구현했다. 공개 텍스트24.43 대 선두47.49의 큰 격차 중 피싱·HoVer·API·의도 분류·stance와 형식 변화에 따른 클래스 쏠림을 우선 개선한다. 원본에서 텍스트131,072 + 이미지32,768 문항·2epoch의 후보를 학습하는 서비스를 연결했다. 기존 공개 평가를 끝내고 실제 GPU 사전 점검·전체 이미지 중복 감사·계획 고정을 통과한 뒤 시작하며, 완료 후 텍스트37개·비전11개를 모두 다시 평가한다. 아직 새 후보의 학습 완료나 순위 달성을 뜻하지 않는다.

**비전 전체 비교 종료 후 확인한 우선순위:** 같은 공식11개에서 파일럿46.0488 대 로컬 QEV52.8900이었다. 가장 큰 격차는 Mind2Web 정확도50.26% 대83.35%(공개 지수 차이 기여4.53점), 다음은 KIE83.61% 대95.01%(1.92점)다. 두 과제가 전체6.84점 차이의 대부분을 설명한다. 이번 고정 확대 후보의 CORD/FUNSD는 KIE 감독을 추가한다. Mind2Web 행동/요소 선택 학습 분할은 현재14개 이미지 출처에 없고, Screen2Words 화면 요약을 그 감독과 동일하게 간주하지 않는다. 다음 비전 데이터 보강에서는 기존 Mind2Web train 변환기의 활용을 우선 검토한다. 이미 검증·고정한 실행의 데이터를 중간에 바꾸지 않는다. 세부 기여와 원본 metric은 `runs/champion-v1/joint-g7-v2/weakness-analysis.json`에 보존했다.

그 결과와 기존 위키·Hub 근거로 점수를 제한하는 과제군, 학습 신호·라벨·선택지 형식의 누락을 찾고, g7 텍스트와 검증된 이미지 학습량을 확대한다. 확대의 목표는 두 트랙의 선두 대비 격차 축소다. 기존 Crystal과의 내부 진단 격차만을 이유로 텍스트 단독16k 대조를 다음 필수 실행으로 지정했던 제안은 철회한다. 공동 학습 간섭 대조는 구체적인 보존 실패를 해결하는 데 필요할 때만 추가한다. 모든 후보에서 두 모달리티를 평가하고, 최종 후보를 고정한 뒤 공식 비공개 평가로 양쪽1위를 확인한다.

**첫 단계는 근거·데이터·채점 경로 감사다.** GPU로 causal/양방향을 다시 비교하는 작업은 취소했다. 기본 형식은 기존 single-code readout, full attention6층 양방향·DeltaNet causal을 이어받는다. 데이터와 학습 예산이 정해진 새 학습에서만 비교용 기준점을 측정한다.

**다음은 검증된 레시피의 규모 확대다.** 원본 `Qwen/Qwen3.5-0.8B` revision `2fc06364715b967f1860aea9cf38778875588b17`에서 넓은 LoRA r16·alpha32·dropout0.05·정답 CE를 시작점으로 삼는다. 기존16k 연구에서 관측한 이득이 큰 데이터에도 유지되는지는 열린 질문이다. 65k급 고유 학습 문항을 첫 규모로 삼고, 최종 quota·seed·step·토큰 예산·비교군은 입력 감사와 속도 측정 뒤 freeze한다. 원래 LR2e-4·warmup/cosine은 재사용 후보이며 대규모에서 검증된 최적값이라고 주장하지 않는다.

**텍스트 데이터:** 최신 g7의113개 출처·quota·변환·dev를 검토 기준으로 삼는다. human/programmatic 라벨과 기존 도구 예외를 대조하고, g7 추가 출처를 현재 로컬 registry와 구별한다. 새 표본은 문서/원본 item 단위로 분할하고, 양성·음성, 유사 오답, 다지선다·장문·다중 질문을 감사한다. phishing·sarcasm 같은 과제의 train dev 정답률이 높다는 이유만으로 배웠다고 결론 내리지 않는다. 별도의 형식·도메인 이동 dev에서 확인한다.

**비전 데이터:** 원본 사람 주석과 프로그램으로 답을 검증할 수 있는 문항을 사용한다. 오답은 같은 이미지의 다른 답 하나로만 만들지 않는다. 출처가 허용하는 경우 다른 이미지의 주석·숫자 변경·같은 장면의 혼동 항목을 섞고, 선택지 수와 정답 분포를 넓힌다. **다른 문자열이라는 이유만으로 오답이라고 간주하지 않는다.** 오답임을 주석/규칙으로 검증할 수 있는 변환만 채택한다. 형식을 바꾼 dev는 이미지·문서 그룹이 학습과 겹치지 않아야 한다.

공식 시험 문항을 학습하지 않는다. 공개 벤치마크의 train split은 허용 여부·라이선스·원본 중복을 확인하고 공개한다. 그 train split을 사용한 결과는 해당 출처에 대한 zero-shot 일반화로 보고하지 않는다. 평가 source의 train split을 전부 제거한 기존 clean 실험은 강한 일반화 진단이며, 모든 train split 사용이 규칙 위반이라는 뜻은 아니다.

두 트랙을 처음부터 함께 다루기 위해 첫 파일럿은 텍스트·이미지 각16,384행의 공동 학습으로 구체화했다. 65k급 확대에 앞서 계산량·두 성능의 변화·출력 복원을 점검하는 단일 seed 탐색이다. 모달리티별 어댑터 분리는 후속 비교 후보이며, 정확도 향상이 검증된 기본값이 아니다. 고유 문항·update·처리 토큰·학습 시간을 함께 기록한다.

## 실험을 추가하는 조건

새 실험에는 근거 링크, 아직 답하지 못한 질문, 바꾸는 변수, 주 지표·보존 지표, 실행 예산, 중단·확대 기준을 먼저 적는다. 기존 결론과 같은 질문이면 실행하지 않는다. 같은 설정의 저렴한 smoke는 런타임 검증으로 구별한다.

- 첫 결과가 실패하면 seed를 계속 늘려 유리한 평균을 찾지 않는다. 명백한 실패와 미세한 차이를 구별하고, 확인 비교의 seed 수는 먼저 고정한다.
- 기존 연구에서 작은 차이는5seed가 필요했다. 새 핵심 비교도5seed를 기본 확인 예산으로 잡고 실제 소요 시간은 smoke로 측정한다. 비용상 줄이면 탐색 결과임을 명시한다.
- 학습 행 수가 같아도 길이가 다르면 계산량이 다르다. 고유 문항·반복 횟수·update·총 토큰·시간을 함께 기록한다.
- NLL만 좋아지거나 공개 점수만 좋아졌다고 공식 Full 개선을 선언하지 않는다. 최종 후보를 고정한 후 공식 suite·속도·입력 용량·전체 파라미터·저장/복원 일치를 확인하고 제출한다.

## 현재 실행 증거

- `qwen_decision/v3/champion_audit.py evidence`: 기존 실험 JSON·위키·코드·현재 보드의 해시와 주요 검정을 통합한다. GPU 모델을 다시 실행하지 않는다.
- 기존 `restore-audit`/`audit` 명령은 **g6 전용**이다. 고정 백업에서 g6 train/dev·manifest·JEVal을 복구하고 전체 g6 행을 검사했다. g7 감사 명령으로 사용하지 않는다.
- g7 원본 data manifest·학습 manifest·best·complete·merge는 `runs/champion-v1/g7-review/`에 복구했다. [검토 요약](champion-v1-g7-review.json)에 revision·해시·학습 설정과 g6→g7 차이를 저장했다. g7 전체 train/dev와 비전12출처는 `runs/champion-v1/joint-g7-v1/`에 복구했다. 공동 파일럿은 g7 전체 행의 출처·라벨·target·count를 검사하고 선택 후보에 기존 오염 필터를 재적용한다.
- 복구한 파일은 곧바로 새 학습셋이 되지 않는다. 새 표본의 라이선스·시험 오염/근사 중복·평가 경로와 계획 freeze가 남는다. 비전 데이터 복구·감사는 별도다.
- 상태는 `runs/champion-v1/input-status.json`, 결과는 `input-audit.json`, 다운로드 revision/해시는 `restoration.json`에 저장한다. 실패하면 traceback을 남기며 학습으로 넘어가지 않는다.

학습·추론 코드를 재사용하면서 과거 실행 증거와 체크포인트는 수정하지 않는다. 현재 프로젝트의 준비 작업은 1위 달성과 구별한다.

### 11-04 g6 참고 감사에서 확인한 것

text train699,960행과 dev30,832행을 복구했다. 원본 모델 파일은 공식 LFS SHA256과 같았다. 저장된 원본 item/document 키의 train/dev 중복은0, 기존 fresh와 정규화 상태가 같은 train 행도0이었다.

train의 고유 ID는699,954개로6행의 ID가 추가로 겹친다(MNLI4, FinTweet2). 각각 전체 row 내용은 달랐다. 확인한 MNLI 변형은 질문·상태와 target이 함께 바뀌므로 ID 중복만으로 상충 라벨이라고 결론 내리지 않는다. 새 표본에서는 원본 ID와 변형의 식별자를 분리하고, 원본 item 그룹을 유지해야 한다.

첫 상태 중복 검사는 빈 state를 갖는 WinoGrande·유머 비교·sarcasm pair 등을 함께 잡았다. 이 문항은 실제 내용이 질문·선택지에 있어 **빈 state 공유는 누수 증거가 아니다.** 해당1차 결과를 보존하고 전체 입력으로 다시 검사했다. g6에서 `state+question+criteria` 전체 입력의 train/dev 중복은0, 같은 전체 입력에 서로 다른 target이 저장된 사례도0이었다. 선택지 dictionary 순서를 정규화할 때 target도 옵션 키에 맞춰 정렬했다. 이 결과는 g7에 외삽하지 않는다.

감사 코드의7개 검사는 파라미터 크기 집계, 도구 라벨 예외, 잘못된 target·item, 중복 ID 내용, 빈 상태, 선택지 순서와 target 정렬을 확인했다. 이 검사는 성능 개선 실험과 구별한다.

**본학습 시작 확인(11-05 00:49 KST):** `joint-g7-v2`는173 update까지 진행됐고128 update checkpoint의 가중치·FP32 master·optimizer·RNG 저장을 검산했다.186개 LoRA B tensor가 모두 실제로 변했으며 loss·gradient가 유한하다. `champion-scale-v2` 서비스가 계속 실행 중이고 사용자 linger를 켰다. 시작 확인 원본은 `runs/champion-v1/joint-g7-v2/training-start-confirmation.json`, 최신 진행은 같은 폴더의 `status.json`·`pipeline.json`으로 확인한다.
