## 학습 셋 (`qwen_decision/v3/vision_mix.py`)

받은 학습 출처를 모두 보드와 같은 객관식으로 바꿨다.
- 이미지는 state이고, 질문과 선택지는 키트의 A·B·C 글자 아래에 둔다(`rows.request`). `VisionEngine`의 decide 프롬프트와 같다.
- 학습 때는 텍스트 학습(`train.Renderer`)처럼 선택지 순서를 섞는다. 코드는 그대로 두거나, 섞거나, 255개 중에서 뽑는다.
  - 순서가 정해진 문항은 섞지 않는다: Yes/No, 작은 것부터 늘어선 숫자, 이미지에 그린 글자.
- 정답은 사람이나 프로그램이 만든 것만 쓴다.
- 자유 답 문항은 같은 이미지의 다른 답, 그다음 같은 출처의 같은 종류 답에서 오답 3개를 뽑는다. 숫자는 키트의 `numeric_distractors`를 쓴다.

**변환 모듈 네 개를 만들었다:** `vision_convert_cauldron.py`, `vision_convert_spatial.py`, `vision_convert_screen.py`, `vision_convert_misc.py`. 출처당 상한은 4,000이다. The Cauldron subset은 2,000, 분류 셋은 1,500으로 더 낮다.

**뺀 것과 이유**
- **HPatches(1,080문항, 만들었지만 학습에서 뺐다).** BLINK의 시각 대응 과제가 HPatches에서 만들어졌다. 공개 보드 이미지와 같은 sequence 62개를 빼도, 남은 54개가 BLINK test(보드 비공개 절반)에 있을 수 있다(`vision_mix.LEFT_OUT`).
- **nuScenes-QA:** 질문이 360° 장면 전체(카메라 6대와 LiDAR)에 대한 것이라 이미지 한 장으로 답할 수 없다.
- **AndroidControl:** 요소 상자가 없어 Mind2Web 형식을 만들 수 없다.
- **The Cauldron의 robut_sqa:** 질문 바꿔 쓰기가 모델이 쓴 것으로 보인다. **spot_the_diff:** 자유 서술 답이다.
- **ChartQA machine 질문:** T5가 만들었다.
- **MegaDepth:** HF 파일 하나가 403을 내서 받지 못했다.

**중복 제거(`vision_mix dedupe`):** 학습 이미지마다 sha256과 64비트 difference hash를 구해, 보드 vision 이미지 10,742장과 다른 벤치마크 시험셋 이미지와 비교했다. 같은 sha256이거나 해시 차이가 2비트 이하면 그 문항을 뺐다.
- 142,993문항 중 1,229개(0.9%)를 뺐다.
- 정확히 같은 이미지: COCO 캡션 34, GQA 3, VQAv2 2, OK-VQA 2. CV-Bench가 쓰는 COCO 이미지와 겹친다.
- 해시가 비슷한 것: 표(multihiertt 250, tat_qa 76)는 흰 바탕이 비슷해서 생긴 오탐으로 보인다. Hateful Memes 115는 split 사이에 다시 쓰인 밈일 수 있다. 어느 쪽이든 빼는 쪽이 안전하다.

**섞는 방법(`vision_mix mix`)**
- 출처마다 64문항을 dev로 떼어 둔다(57개 출처, 3,648문항).
- 이미지 문항은 분야 15개에 똑같이 나누고, 분야 안에서는 출처에 똑같이 나눈다. 출처가 작아서 다 못 채우면 남은 몫을 다른 출처로 돌린다.
- 텍스트 판정 문항을 1/3 섞는다. v3-gold6(기본 모델의 학습 데이터)에서 고르게 뽑는다.
- 거르기 셋 `screen-16k`: 16,384행이다. 이미지 10,923행(분야마다 728~729행)과 텍스트 5,461행이다.

## 학습 (`vision_train.py fit`)

| 항목 | 값 |
|---|---|
| 출발점 | wise80 g6+g7e2(양방향) |
| LoRA | rank 16, alpha 32, dropout .05, lr 2e-4. LM은 attention 6층의 q/k/v/o와 MLP 24층 전부(텍스트에서 가장 좋았던 attn-mlp) |
| 거르기 arm | `frozen`: ViT 동결. `vit`: ViT에도 LoRA(qkv, proj, fc1, fc2) |
| 일정 | 한 번만 지나간다. step당 16행, warmup 1/16 뒤 cosine으로 10%까지(텍스트 거르기와 같다) |
| 손실 | 정답 CE. 텍스트 행은 `train.gold_targets`를 쓴다 |
| 텍스트 행 | `train.Renderer`에 train.py 기본값(pad .35, noul→choice .2, 코드 섞기 .2, 코드 뽑기 .2) |
| 속도 경로 | `fast`(8k microbatch, 체크포인팅 없음), `fast-vit`(4k) — [속도 페이지](vision-train-speed.md) |

**평가는 학습과 같은 packed forward로 하고, augmentation은 쓰지 않는다.**
- 다른 벤치마크 시험셋 17개(4,772행)의 지수가 고르는 기준이다.
- 이미지 dev(출처 평균 정답률)로 학습 출처를 잘 배웠는지 본다.
- 텍스트 dev는 v3-gold6 dev에서 출처당 24행, 2,448행이다. 텍스트 능력이 유지되는지 본다.
- 보드 공개 vision 셋은 본 학습 뒤에만 쓴다.
- 확인: 학습하지 않은 wise80을 이 경로로 재면 시험셋 지수가 50.83이다. 키트 runner의 50.91과 같다(벤치마크별 차이 ±0.02 이내, BF16 반올림).
- LoRA를 합친 checkpoint(`merge`)는 LoRA 모델과 320행 중 318행이 같은 답이다(logit 최대 차이 0.13).

**순서(스크립트 하나로 이어 돌린다)**
1. 중복 제거와 거르기 셋.
2. 기본 모델 기준점(같은 평가 셋).
3. seed 1·2·3마다 frozen과 vit.
4. `report`: 시험셋 지수 차이와 paired bootstrap(벤치마크 안에서 행을 다시 뽑고, seed 평균 정답 여부 사용).
5. 시험셋 지수 평균이 높은 arm을 고른다.
6. Hypersim 다운로드가 끝나면 그 출처를 다시 만들고, 6.5만 행(`main-65k`)으로 본 학습을 한다.
7. LoRA를 합치고 키트 runner로 보드 공개 vision 셋을 잰다.

## d3-lite와 비교 (11-02 실측)

**재는 방법**
- 모델은 `vllm-sr/d3-lite`이고, revision `03560c26`을 `models/d3-lite`에 받았다. README에 따르면 보드가 잰 v3.1.0과 가중치가 같다.
- 엔진은 d3 패키지의 `D3Engine`을 감싼 [`qwen_decision/v3/vision_d3.py`](../../qwen_decision/v3/vision_d3.py)다.
  - 키트 runner가 넘기는 `image_root`와 `prompt` 힌트를 D3Engine이 받지 않아서 감쌌다.
  - 이미지는 우리 VisionEngine처럼 키트의 1.6MP 제한(`images.pil`)으로 읽어 PIL로 넘긴다.
  - 프롬프트는 d3가 자기 방식으로 만든다.
- 환경은 `.venv-di`다. `requirements-v3.lock`에서 다시 만들었고, transformers 5.17.0으로 d3가 검증한 버전과 같다.
- 결과는 `runs/vision/d3-lite/`(보드)와 `runs/vision-heldout/d3-lite/`(시험셋)에 있다. 두 실행 모두 오류 없이 전부 답했다(11,410행, 4,772행).

**이 측정이 보드 척도와 맞는지 확인**
- d3-lite README의 Winoground 57.0을 더해 11개로 계산하면 48.19다. 보드 공식 공개 점수는 47.9로, 0.3점 차이다.
- README의 벤치마크별 숫자 중 †(d3 쪽이 근사로 다시 만든 셋) 표시가 없는 6개는 우리 측정과 1점 안쪽으로 맞는다.
- † 표시가 있는 4개는 README 숫자가 높았다: CharXiv 65.7 대 53.6, KIE 93.2 대 76.2, Mind2Web 53.1 대 50.8, InfographicVQA 74.9 대 73.2. README 숫자로 계산한 50.87과 보드 47.9의 차이는 여기서 나왔다.

**해석**
- **본 학습의 보드 +9.1점은 대부분 겹친 출처에서 나왔다.** 겹침을 빼니 wise80 대비 +1.07 [−0.20, +2.35]만 남았다.
  - 8.03점이 줄었다. Mind2Web·KIE·Hateful Memes(같은 벤치마크의 train split)가 6.06점이다. BLINK가 1.30점, RealWorldQA가 0.50점이다.
  - KIE와 Hateful Memes는 wise80 점수로 그대로 돌아갔다. 이 둘의 이득은 전부 train split에서 왔다.
  - Mind2Web은 wise80보다 +8.3점 높게 남았다. 남긴 웹·앱 출처(AitW, OS-Atlas, RICO-ScreenQA)에서 온 것으로 보인다.
- **BLINK의 상승은 대부분 SPair-71k에서 왔다.**
  - 의미 대응, 시각 대응은 wise80과 같은 점수로 돌아갔다. 기능 대응도 거의 돌아갔다. 시각 대응과 기능 대응의 원본은 SPair가 아니지만, 같은 대응 형식을 SPair에서 배웠다.
  - 남은 것은 상대 깊이(+6.5)와 다시점(+12.0)이다. 깊이 원본을 뺐는데도 상대 깊이가 남은 이유는 모른다.
- **RealWorldQA도 wise80 수준으로 돌아갔다(45.6 → 41.2).** train split도 원본도 없는 셋이다. 뺀 출처(깊이, 공간 관계, 개수)에서 온 진짜 전이였던 것으로 보인다.
- **처음 보는 벤치마크는 그대로다(51.89 대 51.97).** 다만 안에서는 엇갈린다. 영수증과 깊이 전이는 잃었고, 수학과 개수는 남은 출처의 몫이 늘어 올랐다.
- **텍스트 dev도 그대로다(0.850 대 0.849).** 텍스트를 잊는 정도는 출처 구성과 상관없다.
- **d3-lite보다는 여전히 높다.** 보드 +2.94, 6개 +4.22다. 하지만 대부분 wise80이 이미 가진 차이다(+1.86, +3.52). 시험셋은 같다(+0.03).
- **정리: 겹침 없이 이미지 학습이 보탠 것은 wise80 대비 보드 약 +1점, 시험셋 약 +1점이다.** 둘 다 구간이 0을 포함한다. 보드 공개 vision 점수를 크게 올린 것은 보드 셋 자신의 train split과 원본이었다.
- 같은 현상을 보고한 논문(과제별 SFT는 그 과제만 올린다, LM이 비전 특징을 과제마다 따로 배워야 쓴다, 과제끼리 충돌한다)은 [모달리티별 학습 방식 §8](../papers/vlm-modality-finetuning.md#8-이미지-학습이-처음-보는-벤치마크로-안-옮겨-가는-이유-11-02-추가)에 정리했다.

**다음에 해 볼 것(제안, 미실행)**
- **대응 능력은 평가 원본이 아닌 곳에서 다시 만든다.** 예: 평가와 상관없는 사진에 무작위 homography를 걸고, 대응점은 프로그램이 계산한다. 정답은 프로그램이 정하므로 정답 전용 규칙에 맞는다. 시각 대응(HPatches)과 같은 원리이지만 이미지가 겹치지 않는다.
- 깊이도 같은 방식으로 평가 원본이 아닌 깊이 셋에서 만든다(후보 조사 필요).
- 영수증·서식은 보드 KIE와 다른 원본(예: SROIE, XFUND)을 찾는다. 단, WildReceipt는 시험셋이라 쓰지 않는다.

## 결과: 개수·웹 페이지 보강 (`clean-fix`, 11-02 13:23 ~ 15:39)

**사용자 요청:** "한번해봐". 겹침 뺀 학습에서 찾은 두 원인(개수 분포, 웹 과제 종류)을 메우는 출처를 넣고, 같은 레시피로 다시 학습했다.

**넣은 출처**
- `fsc147_crop`(개수, `vision_convert_spatial.py`)는 FSC-147 train 사진에서 물체가 1~12개 들어간 창을 잘라 낸다.

- 평가 이미지와 dhash가 가까운 항목은 뺐다(fsc147_crop 6개, ground 8개, name 14개).

- **노린 두 문항은 고쳐졌다.** 정답 분포(개수 5~7)와 과제 종류(표시한 요소 읽기)를 맞추니, 해당 문항이 13점씩 돌아왔다. 앞 절의 진단("분야가 아니라 정답 분포와 과제 종류까지 맞아야 옮겨 간다")과 맞는다.
- **하지만 전체 점수는 거의 그대로다.** 보드 +0.83, 시험셋 +0.55로 둘 다 구간이 0을 포함한다. 바로 옆 문항(CountBench 8~10개, element_ground)이 내려서 상쇄했다.
  - 이것도 [§8](../papers/vlm-modality-finetuning.md#8-이미지-학습이-처음-보는-벤치마크로-안-옮겨-가는-이유-11-02-추가)의 과제 간 충돌과 같은 모양이다. 몫이 정해진 분야 안에서 출처를 바꾸면, 기존 출처가 받쳐 주던 문항이 내려간다.
- **wise80과의 차이는 처음으로 보드에서 구간이 0을 벗어났다.** 보드 +1.91 [+0.72, +3.20]이다. 시험셋도 +1.53 [−0.03, +3.18]로 0에 거의 닿았다.
- **seed 하나다.** 겹침 뺀 학습과의 차이(+0.8점)는 seed 차이로도 날 수 있는 크기다. 거르기(16k)에서 ViT 동결 seed 3개의 시험셋 지수는 51.00~52.95로 2점 가까이 벌어졌다.
- 텍스트 dev가 다시 1.1점 내렸다(0.850 → 0.839). 구간 끝이 0이라 우연일 수 있지만, 이미지 출처를 바꿨을 뿐인데 텍스트가 움직인 점은 지켜볼 일이다.

- **바뀐 모양은 원인 분석과 같다.** 섞음을 바꾸면 확신 없던 문항이 이쪽저쪽으로 바뀐다. wise80 대비 시험셋에서 318문항을 새로 맞히고 282문항을 새로 틀렸다(보강은 301 대 278). 오른 벤치마크와 내린 벤치마크가 상쇄된다.
- §8-1의 FLAN 결과와도 맞는다. 과제 다양성의 이득은 큰 모델에서 나왔고, 작은 모델에서는 처음 보는 과제가 오르지 않거나 내렸다.
- **한계:**
  - 두 가지를 한꺼번에 바꿨다(분야 추가와 출처별 균등). 어느 쪽이 무엇을 바꿨는지는 가를 수 없다.
  - seed 하나다. 거르기에서 seed 사이 시험셋 지수가 2점 가까이 벌어졌으므로, 이번 차이는 모두 그 안이다.
  - 새 다중 이미지 과제는 분류 출처의 dev 이미지를 학습에 다시 쓴다. dev 숫자에만 영향이 있다.

## 원인 분석: 처음 보는 벤치마크에서 이득이 작은 이유 (11-02)

**사용자 요청:** "흠 웰케 이득이 적지 ㅠ 원인부터 파악해봐." 새 학습 없이, 이미 있는 9개 모델의 문항별 결과로 쟀다.
- 모델은 원래 Qwen(chat), wise80, 16k 거르기 seed 3개, 65k 본 학습, 겹침 뺀 학습, 보강, d3-lite다.

**결론: 이미지 학습으로 배운 것은 학습한 분포에서만 맞는 쪽으로 움직인다. 처음 보는 벤치마크에서는 확신 없는 문항을 거의 무작위로 흔든다.** 데이터 양이나 남은 여지가 모자란 것이 아니다.

**1. 학습은 됐다. 처음 보는 벤치마크로 옮겨 가지 않았을 뿐이다.**

- 다른 학습도 시험셋 정답률이 모두 69.9~71.2%다. 16k 3개, 본 학습, 겹침 뺀 학습, d3-lite가 다 같다.

**2. 시험셋에서 바뀐 문항은 많지만, 얻은 만큼 잃었다.** 크기가 seed 잡음과 비슷하다.

**3. 움직이는 것은 wise80이 확신하지 못하던 문항뿐이다.** 같은 문항이라도, 학습한 분포에서는 맞는 쪽으로 가고 처음 보는 분포에서는 제자리다.

- Mind2Web은 193개를 얻고 115개를 잃었다(순 +78). 웹·앱 학습 출처와 형식이 같다.
- CV-Bench는 160개를 얻고 117개를 잃었다(순 +43).
- 나머지 8개는 순 −18 ~ +15다. 바뀐 문항이 5~19%여도 얻은 만큼 잃었다.
- 앞 절의 CountBench 5~7개와 action_prediction(+13씩)도 같은 모양이다. 정답 분포와 과제 종류를 맞춘 문항만 맞는 쪽으로 움직였다.

**5. 데이터 양과 남은 여지는 원인이 아니다.**
- 데이터를 4배로 늘려도 시험셋은 그대로다. 16k(seed 3개 평균 52.24)와 65k 본 학습(51.97)은 같은 섞음에서 뽑았다. dev는 약 0.76에서 0.78로 올랐다.
- 여지는 있다. 9개 모델 중 하나라도 맞힌 문항이 89.9%이고, 모두 틀린 문항은 10.1%다.

**해석**
- [§8](../papers/vlm-modality-finetuning.md#8-이미지-학습이-처음-보는-벤치마크로-안-옮겨-가는-이유-11-02-추가)의 문헌과 같은 결과다. 과제별 SFT는 그 과제만 올리고, LM은 비전 특징을 과제마다 따로 배워야 쓴다.
- 우리 데이터로 직접 확인한 것은 세 가지다.
  - 학습한 분포에서는 +7.4점이고, 처음 보는 분포에서는 +0.5점이다.
  - 처음 보는 분포의 변화는 seed 잡음과 크기가 비슷하다.
  - 확신하고 틀린 30%는 이미지 LM LoRA로 거의 고쳐지지 않는다.
- 그래서 같은 종류의 행을 더 넣거나 섞는 비율을 바꾸는 것으로는 시험셋 이득이 크게 늘지 않을 것이다. 노린 문항은 오르지만 옆 문항이 내려간다(앞 절).
- 아직 재지 않은 것이 있다. 학습 step에 따른 변화(중간 체크포인트가 없다)와, seed 여러 개의 LoRA를 가중치로 평균했을 때다.

**텍스트는 일반화가 잘 됐나(11-02 확인)**

사용자 질문: "원래 그런가? 텍스트는 일반화가 잘 된 거 같은데." 텍스트도 새 분야로는 잘 안 옮겨 갔다. 텍스트에서 옮겨 간 것은 주로 고르는 형식이다.
- **보드의 0.8B 미세조정 모델 19개**(보드 `data/index.json`, 10-29 생성, Qwen3.5-0.8B 바탕):
  - 공개 점수와 비공개 same-skills의 상관은 0.97이다.
  - 비공개 new-domains는 둘 중 어느 것과도 상관이 없다. same-skills와는 0.09, 공개와는 −0.08이다.
  - same-skills는 12.8에서 41.3까지 벌어지지만, new-domains는 5.0~13.7에 머문다. crystal(wise80)은 same 39.31, new 10.29다.
  - 보드에는 학습하지 않은 Qwen3.5-0.8B 행이 없어서, 학습 전보다 new-domains가 얼마나 올랐는지는 모른다.
- **우리 텍스트 학습에서도 같은 일이 있었다.** WinoGrande는 내부 dev가 0.85인데 JEVal은 0.63이었다([v3 요약](v3-summary.md)).
- **텍스트 학습이 이미지 시험셋을 +10.4점(40.40 → 50.83) 올린 것은 고르는 형식 덕이다.**
  - 원래 Qwen은 보기가 2개인 문항의 75%에서 A를 골랐다(정답 A는 50%). wise80은 45%다. wise80이 새로 맞힌 851문항 중 70%가 원래 Qwen이 A를 골랐던 문항이다.
  - 정답 없이 글자별 평균 확률로 나눠 A 편향만 지워도 40.40 → 43.34다. 나머지 약 7.5점은 객관식에서 문제와 보기를 읽고 고르는 법을 배운 몫으로 본다. 모든 문항에 쓰이는 능력이라 어떤 벤치마크로든 옮겨 간다.
  - wise80을 causal(chat 경로)로 돌려도 보드 공개 vision이 49.14로, decide(49.05)와 같다. 이득은 추론 때의 양방향 attention이 아니라 가중치에 있다.
- 그래서 텍스트 학습과 이미지 학습이 다르게 일반화한 것이 아니다. 먼저 한 학습이 형식이라는 공통 몫을 가져갔고, 뒤에 한 이미지 학습에는 과제별 몫만 남았다. 과제별 몫은 텍스트에서도 새 분야로 잘 안 옮겨 간다.
- 같은 현상을 보고한 문헌(FLAN의 작은 모델, LIMA, Vision-Flan 등)은 [모달리티별 학습 방식 §8-1](../papers/vlm-modality-finetuning.md#8-1-텍스트-학습은-왜-옮겨-간-것처럼-보였나-11-02-추가)에 있다.

## 바로잡음

- JSONL을 `splitlines()`로 나눴더니 문자열 안의 U+2028에서 줄이 끊겼다. `split("\n")`으로 바꿨다.

## 한계

- **비교 실험용 셋이다.** 비상업·미확인 라이선스 출처와 보드 train split이 들어 있다. 행마다 출처가 남아 있으니, 제출용은 이것들을 빼고 다시 만들어야 한다.
- 출처의 정답 잡음이 그대로 들어온다. Mind2Web 스크린샷과 DOM 상자가 어긋난 경우, GQA의 불완전한 장면 그래프, Places365의 애매한 범주가 그 예다. VQA류 셋은 오답이 다른 이미지의 답이라 가끔 그것도 맞을 수 있다.
- Geometry3K와 The Cauldron의 InterGPS는 같은 도형을 약 1,280개 공유한다.
- GeoQA+는 중국어다.
